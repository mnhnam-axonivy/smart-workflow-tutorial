# エージェントの基本設定

**AgenticProcessCall** は、AIエージェントのステップをプロセス内に直接追加するAxon Ivy要素です。何を質問するか、どのデータを渡すか、回答をどう使うかを定義するだけで、LLM呼び出しは自動的に処理されます。

セットアップするには、Designerでプロセスを開き、**Extension > Program Elements** から **AgenticProcessCall** をキャンバスにドラッグし、ダブルクリックして設定エディタを開きます。

![AgenticProcessCall element](cms:/Files/Images/feature01-01)

---

> **前提条件:** エージェントを実行する前に、プロバイダーとそのAPIキーを設定する必要があります。まだ設定していない場合は、先に [グローバル設定 — variables.yaml](#グローバル設定--variablesyaml) セクションへ進んでから戻ってきてください。

> **このガイドで使用する例: Acme Corp の請求書処理**
>
> Acme Corpはサプライヤーの請求書をメールで受け取ります。従業員がメールを開き、請求書テキストをコピーして、Axon Ivyの **請求書取り込み** タスクに貼り付けます。エージェントはそのテキストを読み取り、請求書番号・サプライヤー名・合計金額・支払期限を含む1文のプレーンテキストサマリーをプロセスデータのStringフィールドに書き込みます。
>
> ![Example process](cms:/Files/Images/feature01-00)
>
> 完成したプロセスは `tutorial/process/tutorial/features/Feature01.p.json` にあります。Designerで開いて読み進めてください。

## 要素の設定

### システムメッセージ

システムメッセージはエージェントの職務記述書です。LLMに対して、役割・行うべきこと・出力形式を伝えます。

**請求書プロセスの例:**

```text
You are an invoice summary agent for Acme Corp.
Read the invoice text and return a single sentence summary containing:
the invoice number, supplier name, total amount, and due date.
Do not add any other commentary.
```

**重要な理由:** LLMにはビジネスコンテキストの知識がありません。明確なシステムメッセージがなければ、LLMは何をすべきかを推測して一貫性のない結果を返します。何を含め、何を省き、どの形式を使うかを具体的に指定するほど、出力の信頼性が高まります。

**仕組み:** システムメッセージはデータの前に `system` ロールメッセージとしてLLMに送信されます。このエージェント呼び出しでモデルが生成するすべての応答に影響します。

ユーザーメッセージと同様に、システムメッセージでも `<%=...%>` 式を使用できます。会社のポリシーや承認上限など、ハードコードしたくない値をプロセスデータから注入できます。[プラクティス 05 — エージェントプロンプト: 明確さと動的コンテキスト] を参照してください。

---

### ユーザーメッセージ

ユーザーメッセージは、エージェントが実行時に処理する実際の入力データです。`<%=...%>` 構文によるIvyScript式をサポートします。

**例:** 請求書テキストを保持するプロセスデータフィールドをバインドします。

```text
<%=in.invoiceText%>
```

この式は実行時に評価されます。`in.invoiceText` は `Feature01Data` データクラスの `invoiceText` フィールドです。

**仕組み:** 解決された値がLLM会話の `user` ロールメッセージになります。エージェントはそれを読み取り、システムメッセージの指示を適用して応答を生成します。ドキュメント処理ではドキュメントのテキスト内容を、会話型エージェントではユーザーの質問を渡します。

> **注意:** ユーザーメッセージが空に解決された場合（フィールドが空、または式の評価に失敗した場合）、Smart Workflowはエージェント呼び出しをスキップし、プロセスはそのまま続行します。ログで `Agent call was skipped, since there was no user query` を確認してください。

## 出力

デフォルトでは、エージェントは **プレーンテキストのString** を返します。これが最もシンプルなケースで、追加設定は不要です。

### 結果のマッピング先

エージェントの出力が実行後に書き込まれるプロセスデータフィールドを定義します。

**例:**

```text
in.summary
```

これにより、エージェントの応答が `Feature01Data` の `summary` フィールド（プレーンString）に書き込まれます。プロセスの後続ステップでそのまま表示・ログ記録・次ステップへの受け渡しが可能です。パースも型変換も不要です。

> **型付きJavaオブジェクト** を返したい場合（複数フィールドを個別の型付き変数として抽出するなど）は [構造化出力] を参照してください。
>
> エディタには **🛠️ Tools**・**🛡️ Guardrails**・**🧠️ Model** グループもありますが、この基本セットアップではすべて空のままにします。ツールは [呼び出し可能プロセスツール]、ガードレールは [出力ガードレール]、プロバイダーとモデルは [モデルプロバイダーの選択]、temperature などの設定は [モデル設定] で説明します。

## グローバル設定 — variables.yaml

### variables.yaml とは？

すべてのAxon Ivyアプリケーションには `variables.yaml` ファイルがあります。これは、コードを変更せずに環境（開発・テスト・本番）間で異なる可能性がある設定値を宣言する標準的な場所です。アプリケーションの設定ファイルと考えてください。プロジェクト内に存在し、バージョン管理されます。稼働中のエンジンでは、ファイルを変更せずに **Engine Cockpit** の **Variables** で同じ変数を変更できます。

ここで宣言した値はIvyScriptのどこからでも `Ivy.var().variable("AI.DefaultProvider")` として利用できますが、Smart Workflowが自動的に読み取るため、自分で呼び出す必要はありません。

### Smart Workflowでの利用方法

Smart Workflowは `AI` ブロックの変数を読み取り、以下を把握します。

- **デフォルトで使用するプロバイダー** — 特定の要素で明示的に上書きしない限り、アプリケーション内のすべての `AgenticProcessCall` が同じLLMを使用します
- **認証方法** — 各プロバイダーブロックにはリクエストを行うために必要なAPIキー（およびエンドポイントやデプロイメント名などの追加設定）が含まれます

つまり、AIの接続設定を1か所で一度だけ行えば、すべてのプロセスのすべてのエージェントが自動的に共有します。

> **注意:** 変数は起動時にキャッシュされるのではなく、**エージェント呼び出しのたびに**読み取られます。プロバイダー、モデル、キーの変更は次の呼び出しから有効になり、再起動は不要です。

### 最低限必要な設定

エージェントを実行する前に、2つの変数に値を設定する必要があります。

| 変数 | 値 |
| --- | --- |
| `AI.DefaultProvider` | `OpenAI` |
| `AI.Providers.OpenAI.APIKey` | 自分のAPIキー |

変数そのものは、インストールしたプロバイダープロジェクト（例: `smart-workflow-openai`）ですでに宣言されています。設定するのは値だけです。

**APIキー**は **Engine Cockpit** の **Variables** で設定します。Cockpitは保存時にキーを暗号化するため、平文で保存されることはありません。スクリーンショットは [モデルプロバイダーの選択] を参照してください。

`DefaultProvider` は同じ場所で設定することも、プロジェクトの `variables.yaml` で設定することもできます。

```yaml
Variables:
  AI:
    DefaultProvider: "OpenAI"
```

`DefaultProvider` は、使用するプロバイダーをSmart Workflowに伝えます。プロジェクトがインストールされているプロバイダーの名前を指定してください。

### サポートされているプロバイダー

各プロバイダーのオプション、実行時のプロバイダー切り替え、同一アプリケーションでの複数プロバイダー使用については、[モデルプロバイダーの選択] を参照してください。

### ファイルの場所

Designerでプロジェクトを開き、`config/variables.yaml` を見つけます。チュートリアルプロジェクトでは `smart-workflow-tutorial/config/variables.yaml` です。

> **注意:** 実際のAPIキーを `variables.yaml` に入力しないでください。平文のまま残り、ソース管理に入ってしまいます。ファイルには `${decrypt:}` プレースホルダーを残し、値はEngine Cockpitで設定してください。

## よくあるミス

初めての場合に間違えやすい点がいくつかあります。エージェントが期待どおりに回答しない場合は、次の一覧を確認してください。

| 症状 | 原因 |
| --- | --- |
| 呼び出しがまったく行われない | ユーザーメッセージが空に解決されました。ログで `Agent call was skipped, since there was no user query` を確認してください。 |
| ログには呼び出しが記録されているが `in.summary` が空 | **結果のマッピング先** の代入に失敗しています。多くは型の不一致です。ログで `Failed to map result to` を確認してください。 |
| 回答に `<%=in.invoiceText%>` がそのまま含まれている | 式を解決できませんでした。データクラスのフィールド名を確認してください。 |
| `Unknown model provider <name>` | `AI.DefaultProvider` がインストール済みのプロバイダープロジェクトと一致していません。 |
| プロバイダーからの認証エラー | APIキーが誤っているか、Engine Cockpitで設定されていません。 |

その他の症状と確認ポイントは [トラブルシューティング] を参照してください。
