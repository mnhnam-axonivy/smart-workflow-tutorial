# ガバナンスダッシュボード

**ガバナンスダッシュボード**（*AI Governance Center*）は、Smart WorkflowがIvyリポジトリに保存する会話記録の上に構築された、すぐに使えるWeb UIです。外部のトレースプラットフォームなしで、プロセスオーナー・コンプライアンス担当者・開発者は、どのケースでAIが使われ、どれだけのトークンをどのモデルで消費したかを確認できます。さらに任意のケースを開いて、すべてのエージェントの会話を読み、統計を確認し、AIアナリストに評価させることができます。

---

> **[観測可能性] をベースにしています。** ダッシュボードはデータを *表示* するだけです — **Ivyでの会話記録** チャネル（`AI.Observability.Ivy.Enabled`）で記録された会話を表示します。エージェントの変更は不要です。
>
> **このガイドで使用する例:** 会話記録を有効にし、いくつかのチュートリアルプロセス — 例えば `Feature01.p.json`（請求書要約）、`Feature05.p.json`（呼び出し可能プロセスツール）、`Feature09.p.json`（出力ガードレール）— を実行してから、ダッシュボードを開いて確認します。

---

## 提供される画面

| 画面 | 表示内容 | AIを使用？ |
| --- | --- | --- |
| **履歴リスト** | 記録されたすべてのケース → タスク → エージェント（トークン・メッセージ数・モデル付き、絞り込み可能） | いいえ |
| **トークン使用量の分析** | 過去7日間のトークン使用量・モデル・応答時間のKPIとグラフ | いいえ |
| **会話の詳細** | 1つのケース内の各エージェントの完全な会話: システムプロンプト・入力・応答・ツール呼び出し・メタデータ | いいえ |
| **分析レポート — Statistic** | ケースごとの指標、エージェントごとのA〜F評価、検出された異常 | いいえ |
| **分析レポート — AI Recommendation** | AIによる評価: 要約・リスク・ツール使用状況・信頼性・効率・推奨事項 | **はい** — 要求時のみ |

---

## Step 1 — 依存関係を追加する

ダッシュボードは独立したAxon Ivyプロジェクト `smart-workflow-dashboard` として提供されています。チュートリアルプロジェクトでは、すでに `tutorial/pom.xml` で宣言されています。

```xml
<dependency>
  <groupId>com.axonivy.utils.ai</groupId>
  <artifactId>smart-workflow-dashboard</artifactId>
  <version>14.0.0</version>
  <type>iar</type>
</dependency>
```

`smart-workflow` の依存関係と同じバージョンを使用してください。独自のプロジェクトでも同じ方法で依存関係を追加し、Designerでプロジェクトの依存関係を再解決させます。

> **注意:** Axon Ivy MarketからSmart Workflowをインストールした場合、インストーラーは `smart-workflow-dashboard` をワークスペースに追加せず、別プロジェクトとしてインポートします。どちらの場合も、ダッシュボードはデプロイ先アプリケーションの会話を読み取ります。

---

## Step 2 — 会話記録を有効にする

会話が記録されるまでダッシュボードは空です。[観測可能性] のIvyチャネルをオンにします。

```yaml
Variables:
  AI:
    Observability:
      Ivy:
        # Enable chat history recording for governance audit.
        Enabled: "true"
```

チュートリアルプロジェクトでは `tutorial/config/variables.yaml` ですでに設定済みのため、実行したすべてのチュートリアルプロセスが記録されます。独自のプロジェクトでは自分で追加してください。

この設定 **以降** のエージェント呼び出しだけがダッシュボードに表示されます — それ以前の実行は記録されていません。

---

## Step 3 — ダッシュボードを開く

プロセス一覧から **Governance Dashboard** プロセス（`smart-workflow-dashboard` プロジェクトに含まれます）を開始します。*AI Governance Center* ページが開き、上部に履歴リスト、下部にトークン使用量の分析が表示されます。

> **重要:** 14.0.0 では、この開始イベントはロールで制限されておらず、ダッシュボードにはアプリケーションで記録されたすべての会話 — プロンプト・応答・ツール引数を含む — が表示されます。ダッシュボードへのアクセスは、会話記録そのものへのアクセスと同様に扱ってください。

---

## 履歴リスト

![ガバナンスダッシュボード — 履歴リスト](cms:/Files/Images/feature16-history-list)

履歴テーブルは記録を **ケース → タスク → エージェント** のツリーとしてグループ化します。各行には次の項目が表示されます。

| 列 | 意味 |
| --- | --- |
| **Case/Task/Agent** | ケース名、タスク、エージェントの要素名 |
| **Last updated** | この行で最後に会話が記録された日時 |
| **Messages** | やり取りされたメッセージ数 |
| **Tokens** | 消費されたトークン数 |
| **Model** | 応答したモデル |

テーブルの上部で次の条件で絞り込めます。

- **ケース** — ケース名・ID・説明
- **モデル** — プロバイダーごとにグループ化
- **期間** — *All time*・*Today*・*Last 7 days*・*Last 30 days*（デフォルト: *Last 30 days*）

ケースの **View details** をクリックすると、会話の詳細が開きます。

記録はエージェントの **要素名** でグループ化されるため、すべての `AgenticProcessCall` に `Invoice Summary Agent` のような意味のある名前を付けてください — そうしないとツリーが読みにくくなります。

## トークン使用量の分析

![ガバナンスダッシュボード — トークン使用量の分析](cms:/Files/Images/feature16-usage-analytics)

分析セクションは、記録された会話の **過去7日間** を要約します。

- **KPI:** Total Sessions・Total Tokens・Avg Response Time・Top Model
- **グラフ:** Token Usage Over Time・Model Distribution・Input vs Output Tokens per Day・Top Processes by Token Usage・Response Time Distribution（`< 5 s`・`5–10 s`・`10–15 s`・`> 15 s`）

コストの要因を見つけるのに使います — 例えば、突然トークングラフの上位に来たプロセスや、想定外のモデルがモデル分布に現れていないかを確認します。

> **注意:** 分析は常に過去7日間が対象です。ケース・モデル・期間の絞り込みは上部の履歴テーブルにのみ適用されます。

---

## 会話の詳細

![ガバナンスダッシュボード — 会話の詳細](cms:/Files/Images/feature16-conversation-detail)

会話ページは1つのケースを表示します。

- **KPI** — Task・Total Messages・Total Tokens・Average Duration
- **Agents by Task** — ケースのすべてのタスクと、その中で実行されたエージェントを移動するナビゲーション
- **エージェントごとのカード** と次のタブ:

| タブ | 内容 |
| --- | --- |
| **System Prompt** | エージェントに設定されたシステムメッセージ |
| **Input** | モデルに送信されたユーザーメッセージ |
| **Response** | モデルの応答 |
| **Tool Calls (n)** | 各ツール呼び出しの入力パラメータと結果 |
| **Metadata** | 開始時刻・モデル・入力/出力/合計トークン数・処理時間 |

**Actions** メニューから **Case Information** を開けます — ケースのID・状態・カテゴリ・作成者・作成日時と終了日時・処理時間・説明、そしてケースのプロセスを表示する **Process Viewer** があります。**Export** は表示されますが、14.0.0 ではまだ利用できません。

*「なぜエージェントはそう判断したのか？」* に答えるための画面です: 正確なプロンプトと入力を読み、どのツールをどの引数で呼び出し、各ツールが何を返したかを確認できます。

## 分析レポート — Statistic

![ガバナンスダッシュボード — 分析レポート Statisticタブ](cms:/Files/Images/feature16-case-statistic)

要約の下にある折りたたみ可能な **Analysis Report** パネルには2つのタブがあります。**Statistic** タブはページを開いたときに記録データから計算されます — AI呼び出しもコストもありません。

- **概要** — ケース・プロセス・エージェント数・合計トークン数
- **Token Usage** — 入力・出力・合計トークン数と、1回の呼び出しの最大値
- **Tool Effectiveness** — 総呼び出し数・エラー・null/空の結果・成功した呼び出し
- **Agent Breakdown** — エージェントごとに: **評価**、モデルと終了理由、メッセージあたりのトークン数、スループット、ケース全体に占めるトークンと時間の割合、ツールごとの表（呼び出し数・成功率・null・エラー）、ガードレールごとの表（passed・failed・fatal・平均ms）、検出された異常

### 異常

| 異常 | 検出条件 |
| --- | --- |
| Excessive duration | エージェントの会話が30秒を超えた |
| Excessive token usage | 会話のトークン数が10,000を超えた |
| Excessive tool calls | ツール呼び出しが10回を超えた — ループの可能性 |
| Stuck loop | 同じツールが同一の引数で5回以上呼び出された |
| High null result rate | ツールが呼び出しの50%超でnullまたは空を返した |
| Truncated output | 応答がモデルの長さ制限で途中で切れた |
| Fatal guardrail results | ガードレールが致命的（fatal）な結果で終了した |

14.0.0 ではしきい値は固定です。

### エージェントの評価

各エージェントは100点から始まり、問題ごとに減点されます。

| 問題 | 減点 |
| --- | --- |
| 検出された異常1件ごと | −15 |
| 応答が長さ制限で切れた | −20 |
| ツールエラー1件ごと | −10 |
| ガードレールの致命的な結果1件ごと | −25 |
| ケース全体のトークンの50%超を消費 | −10 |
| ケース全体の処理時間の50%超を占める | −5 |

| 評価 | スコア | 意味 |
| --- | --- | --- |
| **A** | 90–100 | Excellent（優秀） |
| **B** | 75–89 | Good（良好） |
| **C** | 60–74 | Fair（要注意） |
| **D** | 40–59 | Poor（問題を調査） |
| **F** | 0–39 | Critical（直ちに対応が必要） |

## 分析レポート — AI Recommendation

![ガバナンスダッシュボード — 分析レポート AI Recommendationタブ](cms:/Files/Images/feature16-ai-recommendation)

**AI Recommendation** タブはさらに一歩進みます。**Generate AI Recommendation** をクリックすると、AIガバナンスアナリスト — それ自体がSmart Workflowのエージェント — がケースの統計と会話を読み、構造化された評価を作成します。

| セクション | 内容 |
| --- | --- |
| **Executive Summary** | ケースのAI利用状況の要約 |
| **Risk Assessment** | 運用・コンプライアンス・コスト・信頼性のリスクを、それぞれ *Low*・*Moderate*・*High*・*Critical* で理由とともに評価 |
| **Tool Usage Patterns** | 使用されたツール、その頻度、目立つ点 |
| **Reliability Concerns** | 異常・エラー・ガードレールのイベントと結論 |
| **Efficiency Opportunities** | エージェントごとの所見と具体的な提案 |
| **Recommendations** | 変更すべき点 |

レポートはケースごとにIvyリポジトリに保存されます: ケースを再度開くと最後のレポートとその生成日時が表示され、再生成すると置き換えられます。

**知っておくべきこと:**

- **トークンを消費し、デフォルトプロバイダーを使用します。** アナリストは `AI.DefaultProvider` とそのデフォルトモデルで実行されます。
- **ケースの会話をそのプロバイダーに送信します** — 指標だけでなく、プロンプト・応答・ツール呼び出し・ガードレールの結果も含まれます。ケース内のデータにとってこれが許容されるか確認してください。
- **アナリスト自身の実行も記録されます。** 会話記録がオンの場合、他のエージェント呼び出しと同様に履歴リストに表示されます。
- **評価であり、判定ではありません。** どこを確認すべきかを決めるために使い、所見は会話の詳細で確認してください。

## よくあるミス

- **ダッシュボードが空** — `AI.Observability.Ivy.Enabled` がオフになっているか、オンにする前にエージェントが実行されました。
- **分析が絞り込みに連動すると期待する** — 分析は常に過去7日間を表示します。絞り込みは履歴テーブルにのみ適用されます。
- **エージェントに名前がない** — すべてのエージェントがデフォルトの要素名で表示され、区別できません。すべての `AgenticProcessCall` に名前を付けてください。
- **ダッシュボードを全員に公開する** — 記録されたすべてのプロンプトと応答が見えてしまいます。本番環境に移行する前に、誰が開始できるかを決めてください。
- **機密性の高いケースで確認せずにAI推奨を生成する** — 会話の全文がデフォルトプロバイダーに送信されます。

## サンプルプロセス

ダッシュボード専用のチュートリアルプロセスはありません — 他の機能の会話を表示します。

1. `AI.Observability.Ivy.Enabled` が `true` であることを確認します — チュートリアルの `variables.yaml` で設定済みです。
2. プロセス一覧から `Feature01.p.json`・`Feature05.p.json`・`Feature09.p.json` を実行します。
3. **Governance Dashboard** を開始します。3つのケースが履歴リストに表示されます。Feature 05のケースを開いてツール呼び出しを、Feature 09のケースを開いてStatisticタブでブロックしたガードレールを確認してください。
