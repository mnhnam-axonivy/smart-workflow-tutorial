# エージェントパターン: サブプロセス設計とツールの同一配置

Axon Ivyでは、任意の呼び出し可能なサブプロセスをエージェントの構成要素として利用できます。重要な設計上の判断は**どのように呼び出すか**です: 呼び出し可能なサブプロセスはAIが発見できるツールとして呼び出すこともできますし、決定的なAxon Ivy要素として呼び出すこともできます。この選択が、AIがその呼び出しを制御するのか、プロセスが制御するのかを決定します。

---

> **ベストプラクティスの例:** `best-practices/processes/exercise/purchasing/agents/` の `PurchasingAgent.p.json` は、同一のオーケストレーションフローで両方の呼び出しモードを使用しています:
>
> - `translate` は**ツール**として呼び出されます — `CallSubStart` に `tool` タグが付与されており、システムプロンプトが抽出テキストの翻訳を指示すると、Purchasing Manager Agentが自律的にこれを呼び出します
> - `DocumentReader` は**SubProcessCall**経由でエージェント開始前に呼び出されます — ドキュメントはAIが関与する前に常に無条件で読み込まれます

## 使用する場面

同じAIタスクが複数のプロセスに登場する場合に呼び出し可能なサブプロセスを使用します — 翻訳・OCR・分類・要約などがこれに当たります — タスクに明確に定義された安定したインターフェースがあり、固定された型付き入力と型付き出力を持つ場合。単一の権威あるプロンプトにより、1回の変更でダイバージェントなコピーのリスクなくすべての呼び出し元を修正でき、呼び出し可能なサブプロセスは独立して起動・テストできます。

タスクが1回しか使用されない場合（抽象化は再利用の恩恵なしに複雑さを追加するだけ）、プロンプトが高度にコンテキスト固有でほかで有用にするには完全にパラメータ化する必要がある場合、またはAI呼び出しにエラー境界イベントが必要な場合には呼び出し可能なサブプロセスに抽出しないでください — エラー境界は`SubProcessCall`要素ではなく、サブプロセス内の`ProgramInterface`に配置する必要があります。

---

## 仕組み

呼び出し可能なサブプロセスは`CallSubStart` → `AgenticProcessCall` → `CallSubEnd`と同様にシンプルにも、ビジネスの要件に応じてより複雑にもなります — 開始と終了の間に複数のスクリプト・分岐・ネストされた呼び出しを含むこともできます。呼び出しモードは、オーケストレーションプロセスからどのように呼び出されるかによって決定されます。

![Simple callable agent](cms:/Files/Images/practice02-00)

### ツールとして呼び出す — AI主導

> この機能の完全なセットアップガイドは[Callable Process Tools]を参照してください。

**この方法を使用するのは**、現在のコンテキストに基づいてAIがサブプロセスを呼び出すかどうか・いつ呼び出すかを決定すべき場合です。

呼び出し可能なプロセスは依存する任意のIvyプロジェクトに定義できます。例えば、`smart-workflow-demo`の`TranslationAgent.p.json`は、`best-practices`の`PurchasingAgent.p.json`からツールとして利用できます — 重複なしに。

![Callable agent as tool](cms:/Files/Images/practice02-01)

### SubProcessCallとして呼び出す — 決定的

`SubProcessCall`要素を使用して、AIとは独立した固定のポイントでサブプロセスを呼び出します。AIは関与せず、この呼び出しをスキップしたり並べ替えたりすることはできません。

`PurchasingAgent.p.json`では、`DocumentReader`は`AgenticProcessCall`要素の**前に**`SubProcessCall`経由で呼び出されます。ドキュメントは常に最初に読み込まれ、AIは抽出されたテキストを受け取り、生のストリームは見えません。

> **例:** `PurchasingAgent.p.json`の`DocumentReader`はアップロードされたファイルを無条件に読み込みます — AIはこのステップをスキップしたり並べ替えたりすることはできません。テキストが抽出されて初めてPurchasing Manager Agentが開始されます。

![Callable agent in Axon Ivy process](cms:/Files/Images/practice02-02)

**この方法を使用するのは**、AIが何を決定しようともステップが常に固定された順序で実行されなければならない場合です。

## ベストプラクティス: エージェント固有のツールを同一プロセスに配置する

一組のツールが特定のエージェントのみによって使用される場合、それらのツールをオーケストレーティングエージェントと**同じ`.p.json`ファイル内**の`CallSubStart`要素として定義します。これにより、1つのエージェントに属するすべてのものが1か所にまとまり、他のエージェントが呼び出すことのないファイルで`agents/`フォルダが汚染されるのを防ぎます。

![PurchasingAgent.p.json](cms:/Files/Images/practice02-03)

`PurchasingAgent.p.json`はこの混合アプローチを示しています:

| ツール呼び出し可能 | 定義場所 | 理由 |
| --- | --- | --- |
| `translate` | `TranslatorAgent.p.json`（別ファイル） | 汎用目的 — 翻訳が必要な任意のエージェントが呼び出せる |
| `mapToPurchasingObject` | `PurchasingAgent.p.json`内（同一ファイル） | 購買専用 — Purchasing Manager Agentのみが使用 |
| `calculatePurchasingTax` | `PurchasingAgent.p.json`内（同一ファイル） | 購買専用 — Purchasing Manager Agentのみが使用 |
| `calculateStatistics` | `PurchasingAgent.p.json`内（同一ファイル） | 購買専用 — Purchasing Manager Agentのみが使用 |
| `createSummary` | `PurchasingAgent.p.json`内（同一ファイル） | 購買専用 — Purchasing Manager Agentのみが使用 |

`DocumentReader`はエージェント要素が開始する**前に**`SubProcessCall`経由で呼び出されます — Purchasing Manager Agentのツール配列には含まれていません。これには3つの理由があります:

1. **トークン効率** — ドキュメント抽出は、ファイルサイズや詳細レベルによって大量のテキストを生成する可能性があります。これを決定的なステップとして実行することで、このトークンコストをエージェントの推論ループから分離し、Purchasing Manager Agentのコンテキストを軽量かつ集中した状態に保ちます。
2. **関心の分離** — 抽出はAIの推論を必要としない純粋なI/O作業です。決定的に保つことで、LLMを使わずに独立してテスト・デバッグが容易になります。
3. **キャッシュとべき等性** — 抽出されたテキストは特定のドキュメントに対して安定した成果物です。決定的なステップはキャッシュや事前計算が可能ですが、AIツール呼び出しは完全にスキップされたり、予測不能に複数回呼び出されたりする可能性があります。

### 判断ルール

```text
このツールは複数のエージェントで使用されるか?
  Yes → 別ファイル、再利用可能な呼び出し可能サブプロセス
  No  → オーケストレーティングエージェントと同一ファイル
```

### ツールをオーケストレータから視覚的に分離するためにプロセスレーンを使用する

ツールが同一ファイルに存在する場合、**プロセスレーン**`Tools`を追加して、ツールの呼び出し可能プロセスをメインのオーケストレーションフローから視覚的に分離します。
