# トラブルシューティング

症状から調べてください。各項目に、確認すべき点と、詳細を説明しているガイドを示します。

> **まずログを確認してください。** ほとんどの問題は **Axon Ivy Runtime Log** に1行を残し、多くの場合その行だけで原因が分かります。すべての問題がエラーになるわけではありません。エージェントが回答しないまま終了し、ログの1行だけが残ることもあります。

---

## エージェントが回答しなかった

原因として多い順に並べています。

1. **サーキットブレーカーがオンになっている。** `AI.CircuitBreaker.Enabled` が `"true"` の場合、アプリケーション内のすべてのAI呼び出しが停止します。[サーキットブレーカー] を参照してください。
2. **ユーザーメッセージが空、または式の展開に失敗した。** この場合、呼び出しはスキップされ、プロセスはそのまま続行します。ログで `Agent call was skipped, since there was no user query` を確認してください。下記の *メッセージと式* を参照してください。
3. **ガードレールがブロックした。** 空のガードレールフィールドもアプリケーションのデフォルトを継承するため、何も設定していないエージェントでもブロックされることがあります。[出力ガードレール] を参照してください。
4. **結果をマッピングできなかった。** エージェントは実行されましたが、代入先のフィールドが空のままです。マッピングの失敗はスローされずログに記録されるだけなので、プロセスは続行します。`Failed to map result to <expression>` を確認してください。多くは、結果の型と代入先フィールドの型の不一致です。
5. **ファイルがユーザーメッセージを空にした。** サポートされない拡張子のCMSファイルは、メッセージ全体を無効にし、空のメッセージと同じ「スキップ」のログ行を出力します。[ファイル抽出] を参照してください。
6. **ツールが選択されていない**ため、エージェントが期待した処理を実行できなかった。

---

## エージェントは回答したが、期待どおりではない

1. **実行する代わりに、何をするかを説明する。** たいていはツールが選択されていません。**Available tools** が空の場合、エージェントはツールを一切持ちません。[呼び出し可能プロセスツール] を参照してください。
2. **期待したツールを呼び出さない。** 要素でツールが選択されていない、`CallSubStart` に `tool` タグがない、または説明からモデルがいつ使うべきかを判断できません。
3. **自身の指示を無視する**、または応答に `<%=...%>` 式がそのまま含まれている。下記の *メッセージと式* を参照してください。
4. **ドキュメントではなく一般知識から回答する。** RAGエージェントには、システムメッセージでコレクション名を伝え、必ず検索するよう指示する必要があります。[ツールとしてのRAG] を参照してください。
5. **人間の入力を待って一時停止しない。** システムメッセージで質問するよう指示していないため、モデルが自分で回答できると判断しています。[ヒューマンインザループ] を参照してください。
6. **ドキュメントを見ていないかのように振る舞う。** ファイルはログに記録されずにメッセージから除外されることがあります。存在しないCMSパスや、名前が `.png`・`.jpg`・`.jpeg`・`.pdf` で終わらない `Path`・`File`・`IDocument` が原因です。プロンプトを疑う前に、式が実際に何に解決されるかを確認してください。[ファイル抽出] を参照してください。
7. **プロバイダーがそのファイルタイプを読み取れない。** ローカルでは何もチェックされないため、リクエストはプロバイダーに届き、そこで失敗します。[クイックリファレンス] を参照してください。
8. **エージェントがリストを返せない。** コレクション単体は結果の型としてサポートされていません。そのリストをフィールドとして持つクラスを宣言し、そのクラスを使用してください。[構造化出力] を参照してください。
9. **マスクされた値が応答で復元されなかった。** `PiiMaskingGuardrail` は、応答内のプレースホルダーを完全一致で見つけて値を戻します。モデルが `<EMAIL_9f2c41ab77de>` を「メールアドレス」のように言い換えると、戻す対象がなくなります。小型のモデルや古いモデルで起こりやすい現象です。システムメッセージにプレースホルダーに関するヒントを追加するか、エージェントを新しいモデルに切り替えてください。[PIIマスキングガードレール] を参照してください。
10. **Ollamaで、型付きの結果がプレーンテキストで返ってきた。** OllamaはJSONスキーマとツールを同じリクエストで受け取れないため、エージェントが両方を持つ場合、Smart Workflowはツールを残してスキーマを外します。処理を2つのエージェントに分けるか、別のプロバイダーを使用してください。
11. **出力のばらつきが期待より大きい、または小さい。** エージェントが実際に使用した **Temperature** を確認してください。無効な値は通知なしで `0.0` になります。[モデル設定] を参照してください。

## メッセージと式

どちらのメッセージでも `<%=...%>` を使用できます。次の4つの挙動は、プロンプトが悪いと誤解しやすいものです。

1. **システムメッセージ内のファイルは読み取られません。** ファイルを扱えるのはユーザーメッセージだけです。システムメッセージ内のファイル式は `toString()` で変換されるため、モデルはドキュメントの代わりに `Binary@1a2b3c` のような文字列を受け取り、見ていないドキュメントについて自信を持って回答します。
2. **解決できない式は、そのままのテキストとして挿入されます。** モデルが `<%=in.invoiceText%>` をそのまま返してきた場合、誤っているのはプロンプトではなく式です。
3. **ユーザーメッセージの展開に失敗すると、呼び出し全体がスキップされ**、プロセスは何事もなかったかのように続行します。`Agent call was skipped, since there was no user query` を確認してください。空のユーザーメッセージでも同じ動作になります。これは意図的な動作で、設定途中の要素が作業中に失敗しないようにするためです。
4. **システムメッセージの展開に失敗すると、エージェントはシステムメッセージなしで実行されます。** 回答はしますが、ルールがありません。エージェントが突然指示に従わなくなった場合は、まずここを確認してください。

## 設定

1. **`Unknown model provider <name>`。** `AI.DefaultProvider`、または要素の **Provider** フィールドが、プロジェクトがインストールされていないプロバイダーを指しています。
2. **プロバイダーからの認証エラー。** キーが誤っているか、Engine Cockpitで設定されていません。
3. **モデル名がコンパイルできない。** **Model** はスクリプトフィールドのため、値を引用符で囲む必要があります（`"gpt-4o"`）。
4. **デフォルトモデルが無視される。** 変数名は `Model` ではなく `DefaultModel`（Azure OpenAIでは `DefaultDeployment`）です。
5. **変数を変更しても反映されない。** 変数は呼び出しのたびに読み取られるため、再起動は不要です。Engine Cockpitで正しいアプリケーションに設定したかを確認してください。
6. **ガードレールが正当なテストデータをブロックする。** 空のガードレールフィールドは `AI.Guardrails.DefaultInput` と `DefaultOutput` を継承します。
7. **カスタムのツールやガードレールがピッカーに表示されない。** SPI登録ファイルがないか、プロバイダーがファイルの**1行目**にありません。[Javaツール] と [カスタムガードレール] を参照してください。

## ヒューマンインザループ

`DecisionMaker.resolve()` は黙って失敗することはありません。処理の流れのどこが欠けているかを示す `IllegalStateException` をスローします。これらはBPMエラーではないため、境界イベントではキャッチできません。

| メッセージ | 意味 |
| --- | --- |
| `Found no pending ChatMemory for id` | このIDで保存されたサスペンド中の会話がありません。多くの場合、データクラスに `aiMemoryId` フィールドがなく、IDが保存されなかったことが原因です。 |
| `Found no pending AiMessage for id` | 保存された会話に、ツール呼び出しを要求したモデルのメッセージがありません。 |
| `Found no pending ToolExecutionRequest for id` | そのメッセージのツール呼び出しには、すでにすべて回答があります。例えば、`resolve()` を2回呼び出した場合です。 |

[ヒューマンインザループ] と [会話メモリ] を参照してください。

## キャッチできるエラー

ガードレール違反、サーキットブレーカー、自作ツールがスローするエラーは、いずれもエラー境界イベントで処理できるBPMエラーを発生させます。コードの一覧は [クイックリファレンス] にあります。

## 実際に何が起きたかを調べる

ログだけでは分からない場合は、モデルが実際に受け取った内容を確認します。

- **Ivyの会話記録** — `AI.Observability.Ivy.Enabled` をオンにして [ガバナンスダッシュボード] を開くと、ケースごとに正確なシステムメッセージ、ユーザーメッセージ、ツール呼び出し、ガードレールの結果を確認できます。
- **Arize Phoenix** — LLM呼び出し、ツール呼び出し、ガードレールをトレースとして追跡できます。[観測可能性] を参照してください。
