# エージェントの基本設定

**AgenticProcessCall** は、AIエージェントのステップをプロセス内に直接追加するAxon Ivy要素です。何を質問するか、どのデータを渡すか、回答をどう使うかを定義するだけで、LLM呼び出しは自動的に処理されます。

セットアップするには、Designerでプロセスを開き、**Extension > Program Elements** から **AgenticProcessCall** をキャンバスにドラッグし、ダブルクリックして設定エディタを開きます。

![AgenticProcessCall element](cms:/Files/Images/feature01-01)

---

> **前提条件:** エージェントを実行する前に、`variables.yaml` にプロバイダーとAPIキーを設定する必要があります。まだ設定していない場合は、先に [グローバル設定 — variables.yaml](#グローバル設定--variablesyaml) セクションへ進んでから戻ってきてください。

> **このガイドで使用する例: Acme Corp の請求書処理**
>
> Acme Corpはサプライヤーの請求書をメールで受け取ります。従業員がメールを開き、請求書テキストをコピーして、Axon Ivyの **請求書取り込み** タスクに貼り付けます。エージェントはそのテキストを読み取り、請求書番号・サプライヤー名・合計金額・支払期限を含む1文のプレーンテキストサマリーをプロセスデータのStringフィールドに書き込みます。
>
> ![Example process](cms:/Files/Images/feature01-00)
>
> 完成したプロセスは `tutorial/processes/tutorial/features/Feature01.p.json` にあります。Designerで開いて読み進めてください。

## 要素の設定

### システムプロンプト

システムプロンプトはエージェントの職務記述書です。LLMに対して、役割・行うべきこと・出力形式を伝えます。

**請求書プロセスの例:**

```text
You are an invoice summary agent for Acme Corp.
Read the invoice text and return a single sentence summary containing:
the invoice number, supplier name, total amount, and due date.
Do not add any other commentary.
```

**重要な理由:** LLMにはビジネスコンテキストの知識がありません。明確なシステムプロンプトがなければ、LLMは何をすべきかを推測して一貫性のない結果を返します。何を含め、何を省き、どの形式を使うかを具体的に指定するほど、出力の信頼性が高まります。

**仕組み:** システムプロンプトはデータの前に `system` ロールメッセージとしてLLMに送信されます。このエージェント呼び出しでモデルが生成するすべての応答に影響します。

---

### クエリ（ユーザーメッセージ）

クエリは、エージェントが実行時に処理する実際の入力データです。`<%=...%>` 構文によるIvyScript式をサポートします。

**例:** 請求書テキストを保持するプロセスデータフィールドをバインドします。

```text
<%=in.invoiceText%>
```

この式は実行時に評価されます。`in.invoiceText` は `Feature01Data` データクラスの `invoiceText` フィールドです。

**仕組み:** 解決された値がLLM会話の `user` ロールメッセージになります。エージェントはそれを読み取り、システムプロンプトの指示を適用して応答を生成します。ドキュメント処理ではドキュメントのテキスト内容を、会話型エージェントではユーザーの質問を渡します。

---

## 出力

デフォルトでは、エージェントは **プレーンテキストのString** を返します。これが最もシンプルなケースで、追加設定は不要です。

### 結果のマッピング先

エージェントの出力が実行後に書き込まれるプロセスデータフィールドを定義します。

**例:**

```text
in.summary
```

これにより、エージェントの応答が `Feature01Data` の `summary` フィールド（プレーンString）に書き込まれます。プロセスの後続ステップでそのまま表示・ログ記録・次ステップへの受け渡しが可能です。パースも型変換も不要です。

> **型付きJavaオブジェクト** を返したい場合（複数フィールドを個別の型付き変数として抽出するなど）は [構造化出力] を参照してください。
>
> エディタには **Tools** と **AI Provider** フィールドもありますが、この基本セットアップでは両方とも空白のままにします。これらは [呼び出し可能プロセスツール] と [モデルプロバイダーの選択] で説明します。

## グローバル設定 — variables.yaml

### variables.yaml とは？

すべてのAxon Ivyアプリケーションには `variables.yaml` ファイルがあります。これは、コードを変更せずに環境（開発・テスト・本番）間で異なる可能性がある設定値を宣言する標準的な場所です。アプリケーションの設定ファイルと考えてください。プロジェクト内に存在し、バージョン管理され、Axon Ivyが起動時に読み込みます。

ここで宣言した値はIvyScriptのどこからでも `Ivy.var().variable("AI.DefaultProvider")` として利用できますが、Smart Workflowが自動的に読み取るため、自分で呼び出す必要はありません。

### Smart Workflowでの利用方法

Smart Workflowライブラリは起動時に `variables.yaml` から `AI` ブロックを読み取り、以下を把握します。

- **デフォルトで使用するプロバイダー** — 特定の要素で明示的に上書きしない限り、アプリケーション内のすべての `AgenticProcessCall` が同じLLMを使用します
- **認証方法** — 各プロバイダーブロックにはリクエストを行うために必要なAPIキー（およびエンドポイントやデプロイメント名などの追加設定）が含まれます

つまり、AIの接続設定を1か所で一度だけ行えば、すべてのプロセスのすべてのエージェントが自動的に共有します。

### 最低限必要な設定

エージェントを実行する前に、少なくともプロバイダーとAPIキーが必要です。

```yaml
Variables:
  AI:
    DefaultProvider: "OpenAI"
    Providers:
      OpenAI:
        APIKey: "sk-..."
```

`DefaultProvider` は、使用するプロバイダーブロックをSmart Workflowに伝えます。入力したブロック名と一致する名前を設定してください。

### サポートされているプロバイダー

各プロバイダーのオプション、実行時のプロバイダー切り替え、同一アプリケーションでの複数プロバイダー使用については、[モデルプロバイダーの選択] を参照してください。

### ファイルの場所

Designerでプロジェクトを開き、`config/variables.yaml` を見つけます。チュートリアルプロジェクトでは `smart-workflow-tutorial/config/variables.yaml` です。

> **注意:** 実際のAPIキーをソース管理にコミットしないでください。Axon Ivyの環境変数置換（`${MY_SECRET_ENV_VAR}`）を使用するか、Engineの管理UIで環境ごとに値を上書きしてください。
