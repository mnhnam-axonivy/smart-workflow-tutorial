# 会話メモリ

エージェントは**1回の呼び出しの中**で起こったことはすべて記憶しますが、それ以前の呼び出しのことは何も覚えていません。このガイドでは、`AgenticProcessCall`が何を記憶し、何を記憶しないのか、そして`aiMemoryId`フィールドの本当の役割 — **サスペンドされた**会話を人間のタスクをまたいで引き継ぐこと — を説明します。

---

> **実際の動作を確認するには：** フィーチャー13（[ヒューマンインザループ]）は`aiMemoryId`をパターンの必須要素として使用しています — 請求書承認エージェントがタスクの途中で一時停止し、人間が書面による理由を入力した後に再開します。そのプロセスが`aiMemoryId`の実例です。`tutorial/process/tutorial/features/Feature13.p.json`を参照してください。

---

## 始める前に

エージェントを「以前の会話を覚えているチャット相手」と考えたくなりますが、Smart Workflowではそうではありません。エージェントはプロセスの1ステップです。すべての呼び出しはシステムメッセージとユーザーメッセージから新しく始まるため、毎回の実行が予測可能で再現可能になります。

| スコープ | 記憶されるか | 方法 |
| --- | --- | --- |
| **1回のエージェント呼び出しの中** | はい — すべてのツール呼び出しとその結果を含む会話全体 | 自動 |
| **サスペンドをまたぐ場合**（エージェントが人間の入力を待って一時停止し、再開する） | はい — サスペンドされた会話 | `aiMemoryId`フィールド |
| **別々のエージェント呼び出しの間**（別の要素、別の実行、別のプロセスインスタンス） | いいえ | 自分でコンテキストを渡す — 下記参照 |

---

## 1回の呼び出しの中

エージェントは動作中、完全なメッセージリスト（システムメッセージ、ユーザーメッセージ、行ったツール呼び出し、返ってきた結果）を保持します。そのため、エージェントは`lookupApprovalPolicy`を呼び出し、次に`chooseApprover`を呼び出して、両方の結果を回答にまとめることができます（[呼び出し可能プロセスツール]を参照）。

このリストはツール呼び出しのたびに増え、**上限はありません**。モデルへのリクエストのたびにリスト全体が再送されるため、長いツールループはステップごとにコストが増えていきます。ツールのリストは絞り込み、ツールの結果は小さく保ってください。

---

## 呼び出しの間：何も引き継がれない

エージェントが終了すると、その会話は破棄されます。次の呼び出し — 新しい実行での同じ要素でも、同じプロセスの後続の別のエージェントでも — が知っているのは、自身のシステムメッセージ、自身のユーザーメッセージ、そしてツールが返す内容だけです。

後続のエージェントが、前のエージェントの生成した内容を必要とする場合は、明示的に渡します：

- **プロセスデータ経由** — 最初のエージェントの結果をフィールドにマッピングし、次のエージェントのユーザーメッセージで参照します（例：`<%=in.summary%>`）。
- **ツール経由** — サポートケースの過去のメッセージなど、必要な情報を読み込むツールをエージェントに与えます。

> **マルチターンのチャットを構築する場合：** Smart Workflow 14.0.0には、呼び出しをまたぐ組み込みのチャット履歴はありません。過去のターンを自分で（プロセスデータまたはビジネスデータに）保存し、ターンごとにユーザーメッセージでエージェントに渡してください。

---

## aiMemoryId — サスペンド／再開のハンドル

会話が要素の1回の通過を超えて存続しなければならない状況が1つあります。エージェントが作業の途中で人間の入力を待って一時停止する場合です（[ヒューマンインザループ]）。このためにフレームワークは、プロセスデータクラス内の正確に **`aiMemoryId`**（型：`String`）という名前のフィールドを探します：

1. エージェントが通常どおり動作している間、フィールドは空のままです。
2. ツールがBPMエラーをスローしてエージェントを**サスペンド**すると、フレームワークはそこまでの会話を保存し、そのIDを`in.aiMemoryId`に書き込みます。
3. フローが**同じ**`AgenticProcessCall`要素に再び入り、`in.aiMemoryId`に値がある場合、フレームワークは保存された会話を復元して続行します。要素のシステムメッセージとユーザーメッセージは**再送されません**。
4. エージェントが完了すると、保存された会話は削除され、`in.aiMemoryId`はクリアされます。

> **重要：** `aiMemoryId`はサスペンド／再開のためのハンドルであり、会話履歴の機能では**ありません**。Smart Workflowが自動的に値を設定し、クリアします。
>
> **自分で値を設定しないでください。** `aiMemoryId`に値がある状態で開始したエージェントは、その呼び出しを再開として扱います。システムメッセージとユーザーメッセージはどちらも無視されるため、本来尋ねたかった質問は送信されません。

---

## ステップ1 — データクラスにaiMemoryIdを追加する

![Feature12Dataデータクラス — aiMemoryIdフィールドがハイライト表示されています](cms:/Files/Images/feature12-00)

プロセスデータクラスに`aiMemoryId`という名前の`String`フィールドを追加します：

```json
{ "name": "aiMemoryId", "type": "String" }
```

> フィールド名は**フレームワークの規約**です。正確に`aiMemoryId`とスペルする必要があります。異なる名前のフィールドはフレームワークに認識されません — しかもエラーは報告されず、IDが保存されないだけです。

---

## ステップ2 — エージェントを実行する

`AgenticProcessCall`要素への変更は不要です。設定にメモリに関する項目はなく、データクラスのフィールドだけで十分です。

金額の大きい請求書で[ヒューマンインザループ]のプロセス（`Feature13.p.json`）を実行します。エージェントは自力では処理を終えられず、人に質問してサスペンドされます。その時点でSmart Workflowは会話を保存し、そのIDを`in.aiMemoryId`に書き込みます。

---

## ステップ3 — 確認：メモリIDをトレースする

[ヒューマンインザループ]の請求書承認プロセス（`Feature13.p.json`）でライフサイクル全体を確認できます。すべては**1つのプロセスインスタンス**の中で起こります — `aiMemoryId`がサスペンド中のエージェントの状態を保持するスレッドです：

```text
1. プロセス開始 — in.aiMemoryId = ""（空）

2. エージェントが初回実行
   → in.aiMemoryId はまだ空 — エージェントは通常どおり動作中
   → エージェントが請求書 INV-2025-0892（$12,500）を受け取る
   → 金額が$2,000を超えると判断 — askUserFeedback を呼び出す
   → askUserFeedback が human:decision をスロー — エージェントの実行がサスペンド
   → フレームワークが会話を保存し、そのIDを書き込む:
        in.aiMemoryId = "6407c9bd-be10-4334-9ca9-c9b846fc1f57"

3. タスクリストに「Provide feedback for Invoice Approval Agent」タスクが表示される
   → 人間がタスクを開き、入力：「承認済み — Q3インフラ予算で対応」
   → UserTask の出力コードが実行：
        new DecisionMaker(in.aiMemoryId).resolve("承認済み — Q3インフラ予算で対応")
   → 回答が askUserFeedback の結果として、サスペンド中の会話に書き込まれる

4. フローが同じ AgenticProcessCall 要素に戻る
   → in.aiMemoryId に値がある — フレームワークは新しい会話を始めず、保存された会話を復元
   → サスペンドされた askUserFeedback ツール呼び出しが人間の回答を返す
   → エージェントが承認を確認して終了
   → in.result = "Invoice INV-2025-0892 approved. Reason: 承認済み — Q3インフラ予算で対応"
   → 保存された会話が削除され、in.aiMemoryId は再び ""

5. TaskSwitchEvent が正式な承認タスクを作成
   → 名前：「Invoice INV-2025-0892 Approval」
   → 説明：「Justification reason: 承認済み — Q3インフラ予算で対応」
```

`aiMemoryId`フィールドがなければ、ステップ2でIDを保存できないため、ステップ3の`DecisionMaker.resolve()`はサスペンド中の会話を見つけられず、`IllegalStateException`で失敗します。

## 設定リファレンス

| フィールド | 説明 |
| --- | --- |
| `aiMemoryId`（データクラスフィールド） | サスペンドされたエージェント会話のハンドル。ツールがエージェントをサスペンドしたときにフレームワークが書き込み、エージェントの完了時にクリアします。自分で設定しないでください。 |

---

## よくある間違い

- **`aiMemoryId`をチャット履歴として使う** — エージェントに以前の呼び出しを記憶させるものではありません。サスペンドからその後の再開までの間だけ存在します。
- **`aiMemoryId`を事前に設定する** — フィールドに値があると、その呼び出しは再開として扱われ、システムメッセージとユーザーメッセージは無視されます。フィールドの管理はフレームワークに任せてください。
- **ターン間でメモリIDをリセットする** — 人が回答した後、フローがエージェントに戻る前に`in.aiMemoryId`をクリアすると、エージェントはサスペンドされた会話を見つけられません。ゼロからやり直し、請求書を初めて見るかのように読んで、同じ質問をもう一度します。
- **前のエージェントの処理内容を知っていると期待する** — すべての呼び出しは自己完結しています。前の結果はユーザーメッセージまたはツール経由で渡してください。
- **フィールドの欠落またはスペルミス** — フレームワークはIDの保存を黙ってスキップし、エージェントを再開できなくなります。
- **1回の呼び出し内での無制限な増加** — メッセージリストはツール呼び出しのたびに増え、モデルへのリクエストのたびに再送されます。長いツールループはトークン消費が増え続けます。
